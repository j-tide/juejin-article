# 2026-10-10 AI 热点与文章选题简报

检索范围：2026 年 10 月 7 日至 10 月 10 日上午，重点看最近 72 小时内的论文、代码仓库和可复现材料。今天没有重复 10 月 9 日的 AgentTime、Loud Failures、RECAST、Anthropic OSS Scanner 和 Gemini agent 选题。下面的数字和结论都标注为论文或作者仓库中的报告，尚未当作独立实测。

## 1. RunningTab：给工作区 Agent 加一份环境侧的交付账本

### 热点是什么

[RunningTab：Direct Workspace Interaction with Environment-Side Tabs](https://arxiv.org/abs/2610.10444) 于 2026 年 10 月 7 日提交。论文针对直接在工作区里 `find`、读取文件、生成交付物的 Agent：模型会忘记任务要求、已经读过的证据，或只列出却没有打开的候选文件。RunningTab 把每个任务的 requirements、带路径锚点的 read log 和未打开文件 candidates 存在环境侧；Agent 可以按证据解决要求，结束时还有 finish check。作者在三个 benchmark、三个 LLM 上比较 DWI、模型自记账和 RunningTab，报告 RunningTab 在每个 benchmark 都更好。[论文 HTML](https://arxiv.org/html/2610.10444v1) 还给出了四个操作：`add`、`list`、`show`、`resolve`。

### 为什么值得写

对企业知识库、代码仓库和文档交付 Agent 来说，“能读到”与“最后用上”是两件事。RunningTab 把上下文管理的一部分从提示词搬到了执行环境，关键变化是证据链有来源、未完成要求可阻止交付，而不是再写一段更长的 system prompt。论文表 1 的结果来自作者三次运行的汇总，不能直接等同于所有工作区任务的成功率；真正值得拆的是状态结构、终止门禁、权限继承和存储开销。

### 建议标题

**Agent 读过的文件为什么还是会漏进交付物？RunningTab 把证据账本放到上下文之外**

### 文章梗概

下午要把十几份会议纪要整理成项目决策稿，Agent 明明打开过关键页面，最后却漏掉一条限制条件。问题不一定出在检索，而是“任务还缺什么、哪些证据读过、哪些文件只列未开”没有持久状态。文章先复刻普通终端 Agent 的丢证据路径，再拆 RunningTab 的 requirement、read log、candidate 和 finish check，说明环境侧记录与模型自报清单的差别。随后用小型文档任务实现最小账本，比较遗漏率、工具回合和敏感摘录成本，讨论它与 RAG、引用校验、权限继承及人工复核的边界。

### 结构提纲

1. **从“搜到了”到“交付了”**：用一个多文件报告任务重放上下文滑出窗口后出现的遗漏。
2. **RunningTab 的状态模型**：解释 requirement、read log、candidate 的数据结构，以及环境如何从终端观察中记录它们。
3. **四个操作和终止检查**：跟踪 `add/list/show/resolve` 的执行链，说明引用校验和未完成要求如何影响停止。
4. **和 RAG、模型自记账的对照**：把索引检索、提示词 TODO 与环境侧账本放在同一任务中比较覆盖率与开销。
5. **落到生产系统的边界**：讨论权限、敏感片段、并发任务隔离、账本膨胀和人工复核接口。

### 写作所需证据

- **已有资料**：arXiv 摘要与 HTML 全文；论文表 1 的三个 benchmark、三种 LLM 和多种 baseline；`resolve` 的路径与摘录匹配规则；作者对敏感内容存储风险的说明。
- **需要补做**：读完整附录，确认三个 benchmark 的任务拆分和统计方式；实现一个 20 个 Markdown 文件的最小环境侧账本，分别跑“模型自记账”和“外置账本”；记录漏项数、工具调用数、账本字节数。
- **图示建议**：画“终端观察 → 环境捕获 → 证据摘录 → requirement 解决 → finish check”的时序图，再配一张普通 DWI 与 RunningTab 的状态流对照图。
- **未验证点**：论文以公开 benchmark 为主，尚未验证长时间并发任务、跨权限文件、二进制附件和高频读操作下的存储与延迟；也未验证账本本身被错误摘录时的恢复策略。

## 2. SkillSandbox：技能库先考试，再允许 Agent 继续自我进化

### 热点是什么

[SkillSandbox：Skill Verification via Dynamic Scenario Synthesis](https://arxiv.org/abs/2610.10088) 于 2026 年 10 月 7 日提交。论文认为 Agent 从经验蒸馏出的 skill 可能包含错误步骤，或者只适用于产生它的原任务。SkillSandbox 让 Proposer 提炼“必须保留、可以变化”的条件，Builder 把条件变成可执行的新场景，Verifier 比较同一执行器有 skill 和无 skill 的轨迹，按可执行性、效用和效率给出 Keep/Reject。作者在 ALFWorld 和 WebShop、三个模型上报告了成功率、步数、Recovery 和 Regression 的改进，并公开了一个匿名代码入口：[实验代码](https://anonymous.4open.science/r/skillsandbox-647C/)。

### 为什么值得写

“处理越多越聪明”真正难在经验入库的门槛，而不是把失败总结成几句话。论文的一个实用信号是：未经验证的技能库可能让成功率下降、步数增加；只看原任务回放也不一定能证明技能可迁移。这个切口可以把自进化 Agent 从“不断写记忆”改写成“生成场景、执行对照、记录回归”的工程闭环。作者的 ALFWorld/WebShop 结果是受控实验，不代表技能在客服、代码仓库等开放环境中也能安全迁移。

### 建议标题

**Agent 的技能库越长越好吗？SkillSandbox 先给每条技能安排一场考试**

### 文章梗概

客服 Agent 处理退款工单后总结出“重复扣款先撤销最近一笔”，几天后却把它套到团餐拆单，造成账务错误。技能写入容易，证明能迁移很难。文章区分源任务成功、目标任务可执行和不回归三种证据，再按 Proposer、Builder、Verifier 拆动态场景生成与双轨执行。接着用小型订单环境做 Keep/Reject 实验，记录 Recovery、Regression、步数和场景失败，说明技能库为什么需要准入门禁。最后讨论场景偏差、验证成本、权限隔离和人工批准。

### 结构提纲

1. **经验为什么会变成有害技能**：用跨场景的退款与拆单例子区分“记住步骤”和“能迁移”。
2. **Proposer 与 Builder 如何制造新证据**：解释保留条件、变化变量、环境数据绑定和可执行场景脚本。
3. **Verifier 的双轨对照**：跟踪同一执行器有 skill/无 skill 的对齐状态，推导可执行性、效用和效率评分。
4. **Recovery 与 Regression 一起看**：复现论文指标，说明只看成功率为什么会掩盖技能带来的退化。
5. **从实验库到生产技能市场**：讨论版本、租户隔离、危险动作门禁、验证预算和技能撤回。

### 写作所需证据

- **已有资料**：论文 HTML 的方法章节、`R(k)` 评分公式、ALFWorld/WebShop 设置、三模型对比表、代码入口；论文报告的“未经验证技能会退化”和场景合成收益分析。
- **需要补做**：通读匿名仓库的场景 schema 与执行器接口；做一个包含正常退款、团餐拆单和重复提交的 toy 环境；固定同一个模型，比较原任务回放、随机新任务和动态场景三种验证方式。
- **图示建议**：画技能生命周期图（产生 → 场景合成 → 有/无技能并行执行 → 指标 → Keep/Reject → 版本库），再画 Recovery/Regression 的二象限图。
- **未验证点**：匿名代码和作者自报实验尚未经过独立复现；Builder 生成的场景是否覆盖真实长尾、同一模型既造题又判题的偏差、以及技能组合后的相互干扰，都需要单独验证。

## 3. Before They Can Solve：不用让基础模型跑完整任务，也能估它值不值得后训练

### 热点是什么

[Before They Can Solve：Predicting Post-Training Coding-Agent Performance from Base Models](https://arxiv.org/abs/2610.10478) 于 2026 年 10 月 7 日提交。论文指出，基础模型常常连稳定的工具调用格式都不能生成，直接跑 agentic coding 的 pass@K 会把很多 checkpoint 都判成零。作者回放后训练 Agent 的成功轨迹，在累计 patch 第一次让 verifier 从 fail 变成 pass 的位置标出 decisive step，然后提出三种不要求基础模型冷启动 harness 的筛选：Decisive-Action BPB、Patch MCQ 和 prefix-conditioned pass@K。论文在十组公开 base/post-trained 模型上报告了与 SWE-bench Verified pass@1 接近的排序。[HTML 全文](https://arxiv.org/html/2610.10478v1) 给出了公式和轨迹构造流程。

### 为什么值得写

后训练编码 Agent 最贵的部分往往不是一次前向，而是让每个候选模型完整跑多轮工具、测试和修复。这个方法把“是否值得继续训练”的问题移到已经成功的轨迹和可执行 verifier 上，用一个可定位的修复动作提供更细的信号。它对模型选型、数据筛选和训练预算都有工程价值，但相关性不是因果证明：轨迹来源、verifier 质量、tokenizer 和基础模型家族都可能影响排序。文章适合把“模型能力”拆成工具格式、状态延续、动作选择和最终修复四层。

### 建议标题

**还没跑过完整 coding agent，怎么预测它值不值得后训练？**

### 文章梗概

同一批基础模型要不要继续做 Agent 后训练，常见办法是逐个跑 SWE-bench；但模型可能第一轮工具调用就失败，结果全为零，预算也耗在无辨识度的长轨迹上。文章从成功修复轨迹出发，定位测试第一次由红变绿的 decisive step，再拆 BPB、Patch MCQ 和 prefix-conditioned pass@K。随后实现小型 verifier，把成功动作与同前缀失败 patch 对比，观察排序是否跟后训练结果一致。最后讨论轨迹泄漏、候选动作、相关性误读和跨仓库泛化，划清模型筛选与端到端验收的边界。

### 结构提纲

1. **为什么基础模型的端到端 pass@K 不好用**：把工具格式失败、长轨迹状态失败与真正不会修复区分开。
2. **找到 decisive step**：重放成功轨迹，在每个累计 patch 后运行 verifier，定义第一次 fail→pass 的动作。
3. **三种筛选探针**：分别解释 BPB 的概率质量、Patch MCQ 的对比选择和 prefix-conditioned pass@K 的受限续写。
4. **从轨迹到排序的实验链**：复现十组 checkpoint 的流程，说明 Spearman 排序能回答什么、不能回答什么。
5. **训练团队怎样落地**：把探针放进数据筛选和后训练前的闸门，同时保留真实 harness 回归。

### 写作所需证据

- **已有资料**：arXiv 摘要与 HTML 的 decisive-step 定义、三种 probe 公式、SWE-bench/DeepSWE 轨迹来源和作者报告的排序相关性。
- **需要补做**：选一组可公开获取的 mini-swe-agent 成功轨迹，写 verifier 重放器；生成会失败的候选 patch；比较 all-step BPB、decisive-step BPB、Patch MCQ 和受限 pass@K。
- **图示建议**：画“成功轨迹 → 累计 patch → 测试状态翻转 → 三路 probe → 后训练候选排序”的流程图；配一张完整 Agent 与 decisive-step 局部评测的成本对比图。
- **未验证点**：论文结果依赖成功轨迹和 verifier，尚未说明换任务分布、换测试强度或遇到多次可修复动作时排序是否稳定；不能把相关性直接写成后训练收益。

## 4. SciExam for ENSO：没有标准答案，Agent 怎么证明自己做出的科学模型有用？

### 热点是什么

[SciExam for ENSO：Can AI Agents Build Climate Models?](https://arxiv.org/abs/2610.10513) 于 2026 年 10 月 7 日提交，并公开了 [代码与数据仓库](https://github.com/ylzhang2447/SciExam-ENSO-code)。这是一个让 Agent 从真实观测构建厄尔尼诺—南方涛动低阶随机模型的长时任务：六小时预算分为观测处理、诊断编写和模型开发三阶段；诊断在模型开发前冻结，隐藏 grader 只在运行结束后检查统计性质、变量重建和未见年份预测。作者对十二个 Agent 系统的报告是六个最终模型超过已发表参考模型，并做了隐藏年份、外部资料等控制运行。

### 为什么值得写

科学 Agent 最难的不是写出一段像论文的解释，而是结果没有唯一答案时仍能接受独立检验。SciExam 把“自己决定诊断、自己迭代模型、最后接受盲测”装进一个可复现 harness，给工程师一个比语言模型评审更硬的评测模板。代码仓库还提供 Docker 依赖、数据校验、单模型重评分入口，适合做源码和结果复核。需要把作者的“超过参考模型”限定在这个 ENSO 任务、这套 hidden grader 和一次运行设置内，不能直接外推到通用科研能力。

### 建议标题

**没有标准答案，Agent 怎么做科学？SciExam 把气候建模做成一场盲测**

### 文章梗概

让 Agent 复现论文不难，难的是给它一个没有标准答案的科学问题，判断模型是否有用。SciExam for ENSO 把任务拆成数据处理、诊断冻结和模型开发，分数来自 Agent 看不到的统计、动力一致性和留出预测测试。文章画出 harness 的时间预算与数据边界，阅读 grader、checkpoint 和重评分接口，说明冻结诊断怎样减少“对着分数调参”。随后复核公开模型，讨论最终/最佳 checkpoint、外部资料偏移，以及设计迁移到业务仿真或 A/B 实验的条件，划清候选模型、可复现程序与科学结论的距离。

### 结构提纲

1. **从“像不像论文”转向“能不能通过盲测”**：说明开放科学任务为什么不能只用答案匹配或 LLM judge。
2. **六小时三阶段执行链**：跟踪观测处理门、诊断冻结、模型迭代和容器隔离。
3. **hidden grader 怎样拆分科学质量**：解释统计、变量重建和留出预测三类分数，以及参考模型如何同场评分。
4. **代码仓库里的可复核接口**：运行数据下载、哈希校验、单模型评分和 Docker 隔离，确认论文数字能否重算。
5. **把模板迁移到工程系统**：讨论业务仿真中的隐藏测试、时间切分、诊断冻结和结果审计。

### 写作所需证据

- **已有资料**：arXiv HTML 的三阶段流程、hidden grader 设计、十二系统表格、控制运行说明；GitHub 仓库的 `code/README.md`、数据目录、SHA-256 下载和 `sciexam grade` 快速开始。
- **需要补做**：在临时环境安装 Python 3.10 依赖和 Docker，先重评分一个公开模型，再跑全部 12 个最终模型；记录耗时、失败原因和最终/最佳 checkpoint 差异。
- **图示建议**：画“原始观测 → 冻结诊断 → 模型候选 → 隐藏三路评分”的泳道图；配一张 Agent 可见信息与 grader 保留信息的边界图。
- **未验证点**：作者每个系统只运行一次，最佳 checkpoint 是事后挑选；ENSO 单一物理系统和 grader 设计的代表性仍需独立评审，重跑结果可能受模型服务版本影响。

## 5. RoboJEPA：机器人世界模型开始用缩放定律预测规划能力

### 热点是什么

[RoboJEPA：Scaling Robotic Latent World Models](https://arxiv.org/abs/2610.10515) 于 2026 年 10 月 7 日提交。论文在冻结的 V-JEPA 2.1 表征上训练预测器，混合 23 个公开操作数据集、12 种机器人形态，模型从 22M 扩到 8B 参数。作者报告 latent rollout imagination error 遵循二阶 compute scaling law，并与下游规划表现强相关；模型可用单张目标图像在真实机器人上做长时程规划。论文同时公开 [训练与部署代码](https://github.com/facebookresearch/robo_jepa) 和 [项目网站](https://robojepa.github.io/)，报告超过 50,000 次仿真/真实评估回合。

### 为什么值得写

机器人模型经常展示几段成功视频，却很少回答“再加多少数据或算力，规划会不会稳定变好”。RoboJEPA 的切口是把世界模型的离线预测误差、compute-optimal frontier 和真实任务成功率放在一条可拟合的链上，给训练规模与部署决策提供可讨论的指标。论文里的缩放关系、8B checkpoint 和真实平台结果都是作者报告，需要区分模型误差代理与真正的闭环安全性；目标图像、动作空间、规划器和硬件条件也会改变结论。

### 建议标题

**机器人世界模型也开始谈缩放定律了：RoboJEPA 的误差为什么能预测规划能力**

### 文章梗概

机器人世界模型只展示成功轨迹，很难判断扩大模型、数据或训练算力是否值得。RoboJEPA 把多视角视频、动作和状态压到冻结的 JEPA 表征空间，用预测器想象未来，再用 CEM 规划器朝目标图像搜索动作。文章拆编码器、预测器、解码器和闭环规划接口，解释作者如何从 22M 到 8B 模型构造 compute-optimal frontier，并把 latent imagination error 与规划成功率对齐。随后阅读公开配置，复核小规模缩放拟合，比较仿真与真实任务，讨论外推风险、传感器变化、控制延迟和安全停止条件。

### 结构提纲

1. **世界模型到底预测什么**：区分像素重建、latent rollout 和面向目标的规划评分。
2. **RoboJEPA 的数据与网络接口**：说明冻结 V-JEPA 表征、动作/状态 token、多形态数据混合和解码器的职责。
3. **缩放定律怎么拟合**：重建 compute-optimal frontier，比较标准幂律与二阶形式的外推误差。
4. **预测误差怎样连接到规划**：跟踪 CEM 在单目标图像、固定 horizon 和闭环重规划下的执行链。
5. **从 benchmark 到真实机器人**：对照 DROID、RoboCasa 与真实 Franka 任务，列出算力、数据、延迟和安全边界。

### 写作所需证据

- **已有资料**：arXiv HTML 的架构、23 数据集/12 形态、22M–8B 配置、缩放拟合表、CEM 规划超参数和真实任务结果；作者 GitHub 的训练与部署入口。
- **需要补做**：先下载公开代码和小型 checkpoint，复现一次 rollout error 计算；用公开表格拟合两种 scaling curve，再检查 4B/8B 外推；不具备机器人硬件时只做仿真与离线分析，不虚构实机结果。
