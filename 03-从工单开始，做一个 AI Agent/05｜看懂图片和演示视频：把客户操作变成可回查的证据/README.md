# 看懂图片和演示视频：把客户操作变成可回查的证据

*开头与结尾草稿。人物、工单及 Demo 情节为虚构示例；结尾待实现验证后定稿。*

## 开头

“我点了几次都正常。”阿杰在话题里回了一句。

门店负责人很快发来一段录屏：“你看这个，顾客就是这么点的。”

视频开始时，顾客选了一杯少冰饮品，又用了优惠券。点击结算后，页面转了一下，很快回到原处。只看最后一帧，没有明显报错；把中间那一小段放慢，才能看清闪过一条“价格已更新”的提示。

小林在下面问：“那现在该查价格，还是查按钮没反应？”

原始文字写的是“点不了支付”。如果 Agent 只围绕这几个字找历史工单，很容易把网络、按钮事件和支付服务都列一遍。客户已经上传的操作过程，反而没有参与调查。

前几版留下了附件引用，现在该让它们真正提供线索了。图片需要识别页面和提示，视频需要保留操作顺序，观察还要能指回原始画面及时间点。尤其是这种转瞬即逝的提示，随便隔几秒截一帧可能根本看不到。

但视频也不能告诉我们一切。“价格已更新”说明页面出现了这个提示，不说明一定是哪条计价规则出了错，更不说明后台返回了什么参数。

这一篇把图片和视频解析接到现有流程中。先还原能看到的操作与变化，再决定需要补查哪些证据。我们既看它能否抓住这条短暂提示，也看它在画面模糊、附件失效或文字与视频冲突时，会不会把不确定的内容当成事实。

## 结尾

阿杰点开回复里标出的那段视频，重新看了一遍跳转前的画面。

“这个提示能对上。先查价格变化，别把它写成支付按钮没响应。”

小林把调查方向补进话题。Agent 引用了具体片段，也注明视频没有提供后台返回值，暂时不能断定是哪条规则或哪段代码导致的。

“至少不用再让客户把视频里的过程重新打一遍字。”她说。

这一次，附件里的线索进入了调查，仍然和推断保持区别。阿杰接着打开结算页代码：“我去找这个提示是在哪个分支弹出来的。”

从看见页面变化，到解释触发条件，中间还隔着实现。下一版要把代码读取接上，同时记住这家门店当时用的版本。
