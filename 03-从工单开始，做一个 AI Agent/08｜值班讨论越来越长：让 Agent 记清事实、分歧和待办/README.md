# 值班讨论越来越长：让 Agent 记清事实、分歧和待办

*开头与结尾草稿。人物、工单及 Demo 情节为虚构示例；结尾待实现验证后定稿。*

## 开头

交接班时，接班的同事问：“这批团餐现在是什么情况？”

小林把话题往上翻。最初是门店说少了两杯，后来团餐联系人补充有人临时改过口味。阿杰怀疑页面没有更新，老周查了一部分明细，发现修改时间靠近收单截止点。

“所以现在到底缺两杯，还是两杯口味不对？”

小林没有马上回答。这个问题，前面有人问过；答案夹在一张图片和两条引用回复之间。

这张话题里的材料已经不少，难的是哪些仍然有效。最初的汇总清单后来换过，关于缓存的猜测还没有得到验证，老周说“我来查修改记录”也不等于他已经查完。如果 Agent 把这些内容简单压成一段摘要，很容易把过程中的猜测写成最终结论。

前面的 Demo 已经会查询、看附件和阅读代码，现在需要更认真地维护调查进度：每个子问题是什么，哪些事实有来源，哪些判断被纠正，谁正在查，下一班还缺什么。

这一篇在已有话题状态上补上这些关系。长对话不再全部反复塞给模型，而是保留可展开的原始消息、证据索引和经过修订的摘要；关键纠正到来时，旧结论也要随之失效。

我们会用这次团餐交接检查结果：接班的人能不能不从头翻群，就分清数量问题与口味修改，接着尚未完成的工作往下查。

## 结尾

交接时，小林把整理后的调查记录发给接班同事。团餐数量与口味修改分成了两个子问题，清单版本、已有核对和待查记录分别有出处；缓存仍是未验证的猜测，没有被写成结论。

“那我接着看修改记录，数量先按这份清单核对。”接班同事说。

老周补了一句：“我正在查的那项标着就行，别再开一份一样的查询。”

这张工单还没有因为生成摘要就结束，但交接的人知道该从哪里继续，小林也不用重新讲完整段经过。

有些检查要等前一步，有些可以同时做。既然任务和证据已经整理出来，下一篇可以讨论怎样把其中真正独立的部分分给多个 Agent，以及结果回来后怎样核验。
