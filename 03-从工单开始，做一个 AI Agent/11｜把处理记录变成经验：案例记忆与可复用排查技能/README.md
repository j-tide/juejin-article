# 把处理记录变成经验：案例记忆与可复用排查技能

*开头与结尾草稿。人物、工单及 Demo 情节为虚构示例；结尾待实现验证后定稿。*

## 开头

“这个门店路由，我们上次是不是查过？”

老周看着新话题里的查询过程，认出了几个熟悉的步骤。小林找到之前的记录，往群里一贴：“最后是运营补了活动门店范围。前面那个缓存判断，后来排除了。”

旧话题很长，真正有用的内容分散在不同位置：阿杰先提出一个方向，老周查到反证，运营补充配置，小林最后确认顾客已经可以下单。

如果只记住最后一句“可以了”，下次几乎帮不上忙。如果把整段对话都当成正确经验保存，已经被排除的缓存猜测又可能被拿出来。

还有一个限制：那次适用的是当时的活动和门店范围。把同一套操作直接搬到今天，可能又会错。

我们的 Demo 已经能留下调查记录，现在可以开始从里面整理经验。需要分开保存发生的现象、确认到什么程度、哪些步骤有效、哪些判断被否定，以及经验适用于什么条件。重复验证过的检查顺序，可以进一步整理成带前置条件和退出分支的排查技能。

这一篇先做可审查的案例记忆和技能复用。既要拿后续工单检验它有没有少走弯路，也要准备一个条件不适用的例子，检查它能不能停下来重新调查。

小林说得很实际：“记得上次查过什么就很好，别连上次猜错的也一起学会了。”

## 结尾

小林在候选经验里找到了那次人工纠正：缓存判断被排除，活动门店范围是需要核验的条件，原始消息和证据还在。

“这个得留着。”她指了指被排除的判断，“不然下次又让我找客户刷新。”

老周查看了技能的前置条件。新工单条件对不上时，流程会回到通用调查，而不是强行完成旧步骤。候选经验也有撤销入口，后来确认错误时能够追查受影响的引用。

这次保留下来的不只是最终答案，还有有效步骤和适用范围。不过它是否真的让后面的工单处理得更好，现在还不能凭几段回复判断。

小林问：“少问了几句，是因为更会查了，还是把该问的也省了？”

下一篇用时间隔离的工单回放来比较，把这个问题交给可核对的结果。
